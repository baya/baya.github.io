# RFC — block 区块内容横向滚动条修复（探索空间）

## 目标
修复 `/2017/05/11/7daystalk.html`（源 `_posts/2017-05-11-7daystalk.md`）中 block（代码块 `<pre>`/引用块 `<blockquote>`）内容仍出现横向滚动条的问题。上一轮已修复表格与 `.post-content` 长串折行，本轮聚焦剩余溢出源。

## 已核实的根因
1. **代码块 `<pre>` 是主要溢出源**：文章大量用 `~~~c / ~~~bash / ~~~text / ~~~js` 围栏，内容含超长不可断行串——
   - 最长的代码行 431 字符（第 2680 行，C 代码里的 431 字符 hex 字符串字面量）；
   - 多处 200~420 字符的 hex（交易、scriptSig、Merkle 根等）。
   - 当前 `pre { overflow-x: auto }` + 默认 `white-space: pre`，导致这些长行在代码块**内部**出现横向滚动条，用户仍需左右滚动才能看全。
2. **引用块 `<blockquote>`**：第 2908 行含 66 字符 hex `0x0000…0000`（约 528px，桌面下勉强放得下，窄屏会溢出）。已通过 `.post-content` 的 `overflow-wrap: break-word` 继承覆盖，但可显式加固。

## 可选方案

### 方案 A：让代码块折行（推荐）
`pre` 增加 `white-space: pre-wrap` + `overflow-wrap: break-word`（+ `word-break: break-word` 兼容），长 hex/长代码行自动折行，彻底消除横向滚动条。
- 优点：符合"看到全部内容、无需左右滚动"的诉求；`pre-wrap` 保留缩进与空行，短行不受影响；主题级一次修复全站生效。
- 缺点：极少数依赖水平滚动的超宽 ASCII 图会折行（本文未发现此类超宽图）。

### 方案 B：维持代码块横向滚动，仅修页面级滚动
确认 `pre` 已 `overflow-x: auto` 不撑破页面，仅对 blockquote 显式加固折行。
- 缺点：代码块内部仍有横向滚动条，未满足"看全内容"诉求。**不满足目标，排除**。

### 方案 C：改 Markdown 给超长 hex 手工断行
- 缺点：侵入性强、易漏、需维护，431 字符 hex 人工断行不可行。**排除**。

## 待确认
1. 代码块折行是否可接受（对 C 字符串字面量、hex 串折行无碍；是否需保留 `overflow-x: auto` 作兜底）。
2. 是否同时显式给 `blockquote` 加 `overflow-wrap: break-word`（冗余但加固）。

## 验证
- `jekyll build` 成功；`_site/css/main.css` 含新规则；浏览器确认代码块长 hex 折行、无横向滚动条；短代码块与 ASCII 图不回归。
